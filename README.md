# إنجاز — نسخة الويب متعددة المستخدمين

**الحالة:** نسخة أولية (Pilot) قابلة للتشغيل والنشر، **غير معتمدة للاستخدام مع البيانات الحساسة دون مراجعة أمنية مؤسسية**. هذه النسخة جديدة كليًا من جهة الخادم؛ نموذج HTML السابق يعمل محليًا ولا يمكن ترحيل بياناته تلقائيًا.

## المكونات

- خادم FastAPI مستقل، واجهة عربية متجاوبة دون مكتبات CDN أو اعتماد على Microsoft Teams لإدارة المهام.
- قاعدة PostgreSQL في الاستضافة، مع إمكانية اختبار محلي بقاعدة SQLite.
- مستخدمون وأقسام وحسابات بأدوار **مدير عام / رئيس قسم / موظف**. التحقق من الصلاحيات يتم في الخادم لا المتصفح.
- إدارة موظفين مع بريد إلكتروني وكلمة مرور مؤقتة وإجبار تغييرها عند الدخول الأول، وتعديل الاسم والقسم وتفعيل/إيقاف الحسابات.
- مهام، مراحل موزونة، رفع نتيجة المهمة للمراجعة، إعادة للتعديل، اعتماد نهائي 100%، إعادة إسناد المهام، وتقارير أداء.
- محادثة عامة ومحادثات للأقسام والمهام برسائل مخزنة مركزيًا؛ **تحديث تلقائي بالاستطلاع كل 8 ثوانٍ** وليس WebSockets.
- سجل دخول مركزي حسب الموظف/القسم والتاريخ: دخول، خروج، آخر اتصال، مدة الاتصال ومدة النشاط المرصود، حالة اتصال بناءً على آخر إشارة خلال 75 ثانية، وتصدير CSV لكل السجلات أو لموظف محدد.
- سجل تدقيق للإجراءات مع إتاحته للمدير العام.
- ضوابط أولية: تجزئة كلمات المرور Argon2id، جلسة عشوائية مُخزنة بصيغتها المجزأة وخاصية HttpOnly/SameSite، Secure cookie في الإنتاج، CSRF، تقييد فشل الدخول، تعمية الخرج ضد XSS، رؤوس HTTP أمنية، صلاحيات خادم.

> **حدود مهمة:** لا يحتوي هذا الإصدار بعد على Microsoft Entra SSO/MFA، أو المصادقة متعددة العوامل المحلية، أو مرفقات الملفات، أو إشعارات دفع حقيقية، أو سياسات احتفاظ وتدقيق غير قابلة للتغيير، أو استعادة بيانات مجرّبة، أو منظومة تنبيهات تصعيد آلية. لذلك يوصى باستعمال بيانات اختبار غير حساسة فقط حتى استكمال متطلبات الصندوق.

## التشغيل محليًا للتجربة

تحتاج Python 3.12 أو أحدث:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

اضبط متغيرات البيئة (يمكن استخدام ملف `.env` في برنامج التشغيل، أو PowerShell):

```powershell
$env:APP_ENV='development'
$env:DATABASE_URL='sqlite:///./enjaz_local.db'
$env:BOOTSTRAP_ADMIN_EMAIL='admin@example.test'
$env:BOOTSTRAP_ADMIN_PASSWORD='<كلمة_مرور_عشوائية_طويلة_لا_تقل_عن_14_حرفًا>'
uvicorn app.main:app --reload
```

افتح http://127.0.0.1:8000، سجّل دخول المدير العام بالبيانات المحددة، ثم غيّر كلمة المرور المؤقتة. في حال تم إنشاء حساب مدير عام مسبقاً لن تنشئ بيئة التشغيل حسابًا ثانيًا من متغيرات التهيئة. احذف متغير كلمة المرور من بيئة التشغيل بعد إنشاء الحساب. لا تحفظ بيانات دخول حقيقية في GitHub.

## خطوات النشر على Railway (بيئة تجريبية أولاً)

1. **GitHub:** أنشئ مستودعاً خاصاً جديداً باسم `enjaz` أو `enjaz-platform`، وارفع **محتويات هذا المجلد** إلى جذر المستودع؛ لا تستخدم مستودع `npl` الخاص بالتقارير حتى لا يتأثر الموقع الآخر.
2. **Railway:** افتح [Railway Dashboard](https://railway.com/dashboard)، أنشئ مشروعًا جديداً باسم `Enjaz` مستقلاً عن مشروعات التقارير.
3. **قاعدة البيانات:** اختر `+ New` ثم `Database` ثم `PostgreSQL`. اترك منفذ قاعدة البيانات **خاصاً داخل Railway** ولا تضف TCP Proxy عام.
4. **الخدمة:** اختر `+ New` ثم `GitHub Repo` وحدد المستودع الخاص `enjaz`، وسيُستخدم `Dockerfile` تلقائيًا.
5. **المتغيرات في خدمة التطبيق:**

   | المتغير | القيمة |
   | --- | --- |
   | `APP_ENV` | `production` |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` (مرجع من خدمة قاعدة البيانات؛ اختَر المرجع في واجهة Railway، دون نسخ كلمة المرور في المستودع) |
   | `APP_BASE_URL` | اختياري حتى توليد الدومين، ثم `https://YOUR-SERVICE.up.railway.app` أو نطاق HTTPS الخاص |
   | `BOOTSTRAP_ADMIN_EMAIL` | البريد المعتمد للمدير العام |
   | `BOOTSTRAP_ADMIN_PASSWORD` | كلمة مرور مؤقتة عشوائية قوية لا تقل عن 14 حرفًا، تضاف في الإعدادات **فقط للتأسيس** |

6. **الدومين:** ضمن Settings → Networking → `Generate Domain` أنشئ رابط HTTPS للخدمة. إذا غيرت `APP_BASE_URL` إلى الرابط النهائي سيبدأ التطبيق وفق ضبط الإنتاج.
7. **النشر:** راقب `Deployments` و`Logs`، ثم افتح الرابط. جرّب حساب المدير العام، وغيّر كلمة المرور، ثم احذف `BOOTSTRAP_ADMIN_PASSWORD` و`BOOTSTRAP_ADMIN_EMAIL` من متغيرات الخدمة بعد التأسيس. جرب إضافة موظف بحساب مختلف واختبر تسجيل الدخول من متصفح آخر، ثم محادثة مرتبطة بمهمة وتصدير سجل النشاط.
8. **الدومين المخصص:** أضف `enjaz.<نطاق-تملكه>` من Settings → Networking → Custom Domain، وأضف سجل DNS الذي تعرضه Railway لدى شركة الدومين. استخدم HTTPS فقط. لا يلزم دومين جديد إذا كان نطاق مؤسسي فرعي مُعتمد متاحًا.
9. **النسخ الاحتياطي:** فعّل نسخ PostgreSQL الاحتياطية والاحتفاظ بها، واختبر الاستعادة في بيئة اختبار، واضبط المراقبة والتنبيهات والوصول الإداري وأماكن استضافة البيانات وفق متطلبات الصندوق.

**ملاحظة:** توثيق Railway يؤكد دعم نشر Express/خدمات ويب من GitHub، وربط PostgreSQL من خلال الشبكة الخاصة ومتغيرات مرجعية. إجراءات الواجهة قد تتغير؛ استخدم المستندات الرسمية الأحدث عند التنفيذ: https://docs.railway.com/databases/postgresql و https://railway.com/guides/express.

## الجاهزية للأعمال الحقيقية (يجب اعتمادها قبل استخدام بيانات العمل)

- موافقة إدارة تقنية المعلومات والأمن السيبراني والجهات المسؤولة عن البيانات على **الاستضافة الخارجية وموقع تخزين البيانات وتبادلها**.
- ربط هوية المستخدمين بـ Microsoft Entra ID المؤسسي وإلزام MFA، مع إغلاق الدخول بكلمات المرور المحلية بعد الانتقال للهوية المؤسسية.
- تنفيذ فحص أمني مستقل ومراجعة OWASP، واختبارات اختراق وفحص تبعيات وCI، وإدارة الأسرار والتحديثات وصلاحيات قاعدة البيانات وخطة تعافٍ من الكوارث.
- استخدام أداة هجرة قواعد بيانات (Alembic) عند تطوير المخطط؛ `create_all` مناسب للنسخة الأولية فقط ولا يحل محل الهجرة الآمنة للإنتاج.
- سياسة احتفاظ بالسجلات، إبلاغ الموظفين عن آلية رصد النشاط، تحديد المخولين بمشاهدة التقارير، ومراجعة مدى التوافق مع نظام حماية البيانات الشخصية وضوابط الأمن السيبراني المطبقة.
- تأمين التقارير المصدّرة لأنها تحتوي على معلومات عن الموظفين. قياس وجود الصفحة مفتوحة أو التفاعل في المتصفح لا يعني الحضور الوظيفي ولا الإنتاجية.
- تفعيل حدود زمنية لكل جلسة، مراجعة سياسة كلمات المرور، الحماية من إساءة استخدام API على مستوى بوابة الخدمة، توفير التحكم في الوصول الإداري والنسخ الاحتياطي.

## الواجهات API

- `/api/auth/login`, `/api/auth/change-password`, `/api/auth/logout`, `/api/me`
- `/api/users`, `/api/departments`, `/api/tasks`, `/api/tasks/{id}/steps/{id}`, `/api/tasks/{id}/submit`, `/api/tasks/{id}/decision`
- `/api/messages`, `/api/activity`, `/api/activity/pulse`, `/api/activity/export`, `/api/dashboard`, `/api/audit`
- `/healthz`

## بيانات الدخول عند تأسيس النظام

أول حساب هو حساب **المدير العام** الذي تُحدده عبر متغيرات البيئة أعلاه. لا توجد بيانات دخول افتراضية، ولا حسابات وهمية مفعلّة تلقائياً. يقوم المدير العام بإضافة المستخدمين وتحديد الأقسام وإنشاء كلمات مرور مؤقتة؛ ويجب على الموظف تغييرها عند أول دخول.
